# LoafEar · 任务栏字幕条

把本地音频的字幕显示在 Windows 任务栏里，当桌面背景一样常驻，安静地练听力。

- 单文件程序，`publish\LoafEar.exe` 双击即用（约 1.0 MB，需要 .NET 9 桌面运行时）
- 只放**本地音频 + 本地字幕**，不做播放器生态
- 字幕条是任务栏的**真子窗口**（`SetParent` 到 `Shell_TrayWnd`），不是悬浮窗
- 图标为一只面包（`brand.ico`：米黄面包体 + 三条红色割口），exe / 窗口 / 托盘共用同一份矢量渲染

---

## 1. 快速开始

1. 双击 `publish\LoafEar.exe` —— **启动即显示主界面**，同时字幕条贴到任务栏上，
   自动接着上次听的那一集（没设目录、也没听过任何东西时，显示一组测试字幕，告诉你下一步该做什么）
2. 切到「**常规**」页 → 点「选择目录」，选一个**听力目录**
3. 目录里的音频和字幕会自动识别、自动配对、自动开播
4. 关掉窗口，它会收进托盘继续跑（**不弹提示**）；双击托盘图标回来

之后想换一集，两个入口任选：**播放页右下角的「目录」**（点开是听力目录里的节目清单，
最下面一行「其他文件…」挑**目录外**的单文件）、字幕条右键 →「节目」
（目录外文件也会被记住，下次启动照样接着播）。

主界面还有两个入口：**字幕条右键 → 设置**，以及**点托盘图标**。
三者等价，日常不开主界面也能听。

> 曾经做过「静默启动」（开机只出字幕条、主界面全靠右键唤起），冷启动那几秒里右键会卡住，
> 已经撤掉。现在只有「启动即显示主界面」这一种形态，`--silent` 参数不再存在。

---

## 2. 听力目录

**设一次目录就够了，不用再一个个添加文件。**

扫描规则：

- 支持音频 `.mp3 .m4a .m4b .aac .wav .flac .wma .ogg .opus`
- 支持字幕 `.srt .ass .ssa .lrc .vtt`
- 递归子目录（最多 3 层）
- 按文件名**自然排序**：`E01 < E02 < E3 < E10`

字幕配对优先级：

| 优先级 | 规则 | 例子 |
|---|---|---|
| 1 | 同目录 + 同名 | `E01.mp3` + `E01.srt` |
| 2 | 同目录 + 字幕名以音频名开头 | `E01.mp3` + `E01.中英.srt` |
| 3 | 同目录只有唯一一个字幕 | 兜底，避免整集没字幕 |

没配上字幕的节目在右键菜单里会标 `(无字幕)`，仍然可以听。

## 3. 主界面

窗口 540×388（MinWidth 512 / MinHeight 366），**保留系统标题栏**（图标 + LoafEar 名称，
右上角系统按钮走「关闭到托盘」）。标题栏下面一行 40px 纯文字标签：五个标签**宽度跟着字数走、左右统一 28 间距**，
整行与内容区左边缘对齐；当前标签是文字转墨色 + 下方压一条**贴着字宽**的短墨线，
标签行底那条通栏细线（`#DCDDDD`）就压在短墨线的下沿（客户区 y=31），两条线贴在一起、中间不留白，
而且细线画在标签**下面一层**，所以墨线不会被灰线切出缺口；没有 Tab 卡片、没有竖向滚动条
（内容超出时用滚轮滚，不显示条）。

2026-11-08 起主界面按 `loafearui` 设计稿重排，由六个标签改成**五个**：
原「外观」页的设置全部并入「常规」页。播放页右下角四道横线是**目录**（点开是节目清单）；
原来的「更多」浮层（偏移、上句 / 下句、字幕条预览、吸附状态、老板键提示）按这次的要求整块去掉，
偏移挪回「保存」旁边那一行，常驻状态条也换成了 2.4s 后自己淡出的轻提示。

| 标签 | 内容 |
|---|---|
| **播放** | 节目名大标题（只显示，换节目走右下角「目录」）、大字幕卡片（主句 / 译文可编辑 + 保存）、保存 / 偏移 ±ms / 第几句 / 收藏星 / 单句循环、进度条（左当前、右总长）、上一句 / 圆形播放 / 下一句、速度、右下「目录」浮层（节目清单 + 选择其他文件） |
| **收藏** | 筛选（最近 / 本节目 / 全部，**默认本节目**）、句子列表（点星标取消收藏、点整行循环这一句）、右上圆形按钮（连播全部收藏；跑起来变暂停，再点就是暂停 / 继续）、导出 txt |
| **常规** | **听力目录（选择 / 重新扫描 / 已识别数量）**、主题（带框下拉）、五个开关（鼠标穿透 / 截图隐身 / 透明背景 / 投屏隐藏 / 关闭到托盘）、宽度滑条、移开 / 悬停两条透明度滑条、主副字号（**译文 / 时间**两个勾选在副字号右边的同一行）、**靠左 / 靠右吸附任务栏**两颗按钮 + 紧跟其后的**悬浮字幕**开关 |
| **快捷键** | 七个热键的录制（老板键 / 播放 / 上一句 / 下一句 / 单句循环 / 收藏本句 / 偏移 ∓100ms 两个） |
| **关于** | 版本、一句话说明、配置文件路径、字幕格式、协议、检查更新、打开配置目录 |

浮层 / 下拉的默认位置（`CustomPopupPlacementCallback`，两个都带「屏幕放不下就换一种」的候选）：

- **目录浮层**：右边缘对齐四道横线那颗按钮的右边缘，往上弹。浮层 94 宽、按钮只有 32，
  居中的话会盖掉左边一排图标；上面没位置时第二个候选改成往下弹。
- **倍速下拉**：**竖直方向居中**在按钮上（菜单中线压着按钮中线）。它贴着窗口底边，
  往下弹会被屏幕切掉，居中正好上下各露一半；上下都不够时退回「挂在按钮下面」。

**宽度和两档透明度用滑条拖、速度是下拉选，其余数值都是直接填数字。** 改完按回车或点别处生效，越界会自动夹回合法范围。

### 配色：只有黑灰两级

这个程序是摸鱼用的，第一原则是「不该被看见的时候不引起注意」，所以界面里没有第二种彩色：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| 墨 | `#1A1A1A` | 正文、当前标签、主按钮底 |
| 次 | `#3A3A3A` | 次级正文 |
| 说明 | `#787878` | 字段名、时间 |
| 最弱 | `#A6A6A6` | 提示、单位、占位 |
| 描边 | `#EDEDED` / `#E3E3E3` | 卡片 / 控件 |
| 底 | `#FFFFFF` / `#FAFAFA` | 窗口 / 输入框与当前句 |

唯一的实心块只有两处：播放键和「保存」。字幕条深色版是 `#232323` 底 + 白字 + 次级 `#9C9C9C`，
整句一色，不做逐词高亮、不画进度线（2026-10-27 按用户要求去掉了底部那根 1px 进度线，
槽和填充一起删，免得任务栏上多一条多余的横线）。

> 2026-10-27 试过一版「暖白 + 墨绿 + 左侧竖排侧栏」，用了半天就退回来了：
> 摸鱼工具上多一种颜色就多一分被注意到的风险，而且竖排侧栏把常用宽度让给了导航。

### 节目下拉

播放页右上角就是听力目录的一览：点开是一个列表，选中哪一集就换音频、换字幕、直接开播。
列表里带着扫描配对好的字幕；名字太长会截断，悬停能看到完整路径。

- 正在播的那一集永远对得上下拉的选中项，切换后不会错位
- 从 `…` 挑的目录外单文件也会作为一项出现在列表里（下次启动照样选中它）
- 扫不到节目时下拉是空的，靠一行灰色占位文字说明「选择节目」/「未选择节目」

下拉右边的 `…` 只做一件事：挑**目录外**的单个音频。日常换集用下拉就够。

### 当前句可以直接改

「播放」页的「当前句」是个可编辑的文本框：听到字幕打错了、断句别扭，就地改完点**保存**，
直接写回**原字幕文件**（同目录留一份 `.bak` 备份）。改完会重新解析一遍文件，界面上立刻就是磁盘里的内容。

- 支持 SRT / ASS / SSA 等文本格式；UTF-8、UTF-16、GBK 都能原样写回，不会把中文写乱码
- 改错了：同目录的 `<文件名>.bak` 就是上一版

**双语字幕的主句和译文都能改**，两行各自独立保存；保存后预览立刻刷新，焦点还留在编辑框里，不会跳走。

> 中文字幕几乎都会被折成两行（一句台词在文件里占 2 行甚至更多）。所以回写不是「单行精确匹配」，
> 而是**多行窗口匹配**：从当前行开始逐行累加，去掉空白、合并换行后和界面上的句子比对，
> 命中就把这一整段换掉。否则中文字幕一折行就永远「找不到原句」，改完等于没改。

### 字幕条上的三种点击

| 操作 | 效果 |
|---|---|
| **单击** | 暂停 / 继续，跟按空格一样 |
| **双击** | 同样只算一次暂停 / 继续（第二下抬起会跳过，不会切回去） |
| **右键** | 弹出快捷菜单 |

右端不再放任何按钮：字幕条只显示文字，点它不会碰到控件。
单句循环用主界面的 ⟲1 按钮、右键菜单，或者快捷键切换。

> 这些点击都是走**原生窗口消息**判断的，不依赖 WPF 的鼠标路由：
> 字幕条是 explorer 的子窗口，WPF 的输入分发在这种嵌入关系下不保证到位。
> 单击在 **WM_LBUTTONUP** 时切，按下那一刻不会误触发；
> 双击按「两次按下间隔 ≤ 400ms 且位移 ≤ 6px」自己算，判成双击后第二下抬起跳过，所以一次双击只切一次。
> 判定成功后**异步**转给主界面，不在消息处理里直接动布局——跨进程改子窗口布局可能把 explorer 卡住。
>
> 右键菜单同理：**不在窗口过程里搭菜单**。这条消息是 explorer 同步发过来的，
> 在过程里创建 Popup / 设 owner，explorer 会一直等我们返回，表现就是整个任务栏、
> 连资源管理器一起假死。现在窗口过程只记事、立刻返回，菜单由消息队列重新排队后弹出。

### 吸附在任务栏的哪一端

常规页底部一排：**靠左吸附任务栏**、**靠右吸附任务栏**，再往右紧跟着**悬浮字幕**这个开关。
点哪颗吸附按钮就按哪端重算一次位置，并把 `DockSide` 记进配置。

靠右是 `x = 托盘左边 - 宽度`；靠左是 `x = 任务栏左边 + 内缩`。
靠左**不能**拿「任务按钮区右边」当锚点：Win11 把任务按钮居中摆，
那个位置的右边其实是屏幕中间，贴着它看着就像浮在任务栏中间。

### 悬浮字幕（桌面歌词那种玩法）

勾上常规页的**悬浮字幕**，字幕条就不再是任务栏的子窗口，而是置顶浮在屏幕上的一条窗口：

- 上方那一行放**锁按钮**：**只有鼠标压到字幕上才露出来**（用 `Hidden` 不用 `Collapsed`，
  否则这一行会塌掉、字幕条被拉高），吸附在任务栏时整行 Collapsed，窗口高度回到 40；
  锁按钮**没有底板**，图标浮在字幕条正上方居中，浅色桌面上靠一圈淡投影当描边，也没有悬停提示；
- **没上锁**：按住字幕条可以拖到屏幕任意位置，松手时把 `FloatLeftDip / FloatTopDip` 写进配置，
  下次启动还在原地；这一下**不会**触发暂停；
- **上锁**：位置固定，点字幕条就是暂停 / 继续，跟贴着任务栏时一样，只有点锁按钮解锁后才能再拖；
- 取消勾选：浮窗收回、锁按钮收起，自动重新吸附回任务栏的 `DockSide` 那一端。

拖动走的是原生 `WM_LBUTTONDOWN + SetCapture`，不是 WPF 的鼠标事件 ——
窗口带 `WS_EX_NOACTIVATE`，WPF 那层不保证收得到拖动需要的消息。
**锁按钮的点击也走原生那条路**（窗口过程里先判坐标是不是落在锁上）：
所有左键消息都在原生层吃掉了，WPF 的 `Button.Click` 收不到完整的按下 + 抬起，
只挂 `Click` 会出现「点图标没反应」。

拖动 / 摆位的边界用**显示器整块屏幕**（`rcMonitor`，含任务栏），
不用 `SystemParameters.WorkArea` —— 后者把任务栏挖掉了，字幕条永远拖不到屏幕最下面。

## 4. 右键快捷菜单

在任务栏的字幕条上点右键，弹出 **162×244** 的紧凑菜单：

```
   ‹    ▶    ›    ⟲1        ← 一行图标
──────────────────────────
收藏本句          Ctrl+Alt+S
──────────────────────────
变速              0.8×  ›   ← 二级菜单，四档
节目 (24)               ›   ← 二级菜单，一屏 8 项、滚轮翻
──────────────────────────
译文                      √
──────────────────────────
设置
隐藏并暂停        Ctrl+Alt+H  ← 老板键，藏起来的那个状态下写「显示并继续」
退出
```

- **播放控制压成一行图标**，占位从三行降到一行；图标行的播放键和循环键点了当场换样子，不用重开菜单
- **收藏本句紧贴图标行**：它是对「当前这一句」的动作，和图标行是一组；已经收过的写「取消收藏」
- **变速收进二级菜单**（1.0× / 0.8× / 0.6× / 0.4× 四档，和主界面下拉是同一份档位），主菜单只显示当前倍速
- **节目列表收进二级菜单**，**一屏 8 项、鼠标滚轮往下翻**，右侧细滚动条提示还有内容；
  一屏高度按「首行实际行高 × 8」校准，换字体或 DPI 也不会只露半个第 9 项
- **译文**开启时在**右边缘**显示 √，点一下当场切换，菜单不收起
- **时间和透明底**不占菜单位置了，都在主界面「常规」页里，时间默认关
- 图标都是矢量 Path 画的，不依赖图片文件
- 图标行整行不跟着高亮，鼠标只在单个按钮上出现浅灰底
- 所有选项（含带二级菜单的「变速」「节目」）**文字靠左对齐、√ 与倍速数值靠右对齐**：
  文字一列、右侧一列，`√` 和 `0.8×` 落在同一条竖线上，勾不勾选都不会让文字左右乱跳

> 开了「鼠标穿透」后，字幕条收不到鼠标事件，右键菜单也会失效——这是穿透的定义，不是 bug。

## 5. 字幕格式

支持 **SRT / LRC / VTT / ASS / SSA**，UTF-8 或带 BOM 的 ANSI 都能读。

### ASS / SSA 特效

字幕条只有 40 px 高，所以只实现这个尺寸下真正看得见的部分：

| 支持 | 说明 |
|---|---|
| `\k` `\kf` `\K` | **卡拉OK 逐字高亮**，唱到哪个词就亮哪个 |
| Style 主色 / 副色 | 未唱到的字用副色，唱到用主色 |
| `\c` `\1c` | 内联改色 |
| `\b` `\i` | 粗体 / 斜体 |
| `\an1`~`\an9` | 只影响水平对齐（左 / 中 / 右），垂直方向没有空间 |
| `\fad` `\fade` | 淡入淡出 |
| `\N` `\n` `\h` | 换行与硬空格 |

不支持的：绘图指令 `\p`、旋转、缩放、`\pos` 定位、阴影描边——这些在 40 px 高的条里没有意义，解析时安全跳过。

### 长句分页

句子比字幕条宽时**不截断、不滚动，而是分页**——按词边界把整句切成若干屏，每屏只在自己那段时间里显示：

- **屏内文字完全静止**，读完一屏再整体翻到下一屏，左边缘固定不动
- 每屏的停留时间按「念完这一屏要多久」摊分：**按音节算，不是按字数**——一个词的时长约等于
  `70ms + 175ms × 音节数`，词尾是逗号 / 句号 / 省略号 / 破折号再各加 140~320ms 的停顿。
  SRT 没有逐词时间，这是能拿到的最接近口语节奏的估法
- 摊完之后**每次翻页再整体往后让 380ms（约一个词）**，这个余量从末页扣。理由见下面那段
- **页边界永远落在词与词之间**：翻页时裁切窗口会收缩到「这一屏最后一个词为止」，所以左右都不会出现半个单词
- **末页太短就把上一页末尾的词让过来**：末页词数 ≤ 2 或宽度不到条宽 45% 时，把切分点往左挪一个词
  （只挪切分点，末页自己不补内容），挪到末页词数 > 2 且宽度 ≥ 45% 为止
- **让词的边界**：上一页让完至少得剩 3 个词，让完不能超出条宽；两条任一不满足就停手——
  宁可留一页短一点，也不把上一页拆碎、也不让末页横向溢出
- 换句时归零，新句子从第一屏开始

> 为什么不滚动？滚动要眼睛一直追着字跑，而且永远在动；分页是「停下来读完 → 翻页」，
> 精听时不需要追踪，眼睛只在固定位置读取。前两版分别做过匀速滚动和「先停顿再滚」，
> 都还是有"追字"的负担，所以直接换成翻页。
>
> **为什么翻页要往后让，而不是刚好卡在「这页念完」的那一刻？**
> 2026-10-27 用户反馈「长字幕折断不合理，有些音频还没读到就已经折到下一页了」。
> 按比例摊出来的翻页点正好落在「这一屏最后一个词念完」的那一瞬，等于音频刚离开这页、字就没了，
> 正在看的半句被直接抹掉。多留 380ms 之后，音频走到下一屏开头时上一屏的最后几个词还在眼前。
> **宁可晚一瞬，不要提前**——晚了你只是多看了一会儿旧字，提前了你就是丢字。
>
> 这个值是可调的：`config.json` 里的 `PageFlipLagMs`，0~1200 之间，默认 380；填 0 就回到「念完即翻」。

> 代价：因为不切词，每屏右侧可能留下不到一个词的空隙（不会把最后一个词劈开）。
> 实测（`--barshot` 自带样例「It's like, all of my life, everyone has always told me, 'You're a shoe!…」，
> 条宽 420 / 可视 400 / 字号 13）：切成 2 屏，宽度 380（95%）/ 249（62%），
> 起点 x = 0 → 380 首尾相接、无重叠；4.53s 的句子摊成 0~3296 / 3296~4530 ms。

## 6. 变速与单句循环

**变速四档：1.0× / 0.8× / 0.6× / 0.4×，音调不变。** 用 SoundTouch 做时间伸缩，不是改采样率。
主界面是下拉框，右键菜单是同档位的二级菜单，两处共用 `PlaybackSpeeds.All` 一份定义，
手改配置文件里不在这四档的值会被吸附到最近的档。

字幕时钟按「已输出的帧数 × tempo」反推源时间，再扣掉输出缓冲的 120ms，所以变速时字幕不用换算，也不会提前。

倍速的显示文本只有一个格式：`1.0×` / `0.8×` / `0.6×` / `0.4×`。一倍速也写 `1.0×`，
后面不加「原速」两个字——四档同一个写法，下拉框和右键二级菜单里每一项的宽度才是齐的。
（主界面那颗下拉框按 2026-11-19 的要求写成大写 `X`：`1.0X` / `0.8X` / `0.6X` / `0.4X`；
右键菜单不动，仍是 `×`。两处只是文案不同，档位还是同一份 `PlaybackSpeeds.All`。）

**单句循环**：当前这句播完自动回到句首，反复听。按「上一句 / 下一句」换句时循环点会跟着走。
三个入口：字幕条右端的 ⟲1 按钮、主界面图标行、右键菜单；状态是同一个 `LoopSingleCue`。

> **循环开着的时候，「上一句」就是退到上一句**，不会因为「本句已经播过 1.5 秒」而先回到本句开头。
> 循环本来就会不停重来，再让按键变成原地重播，结果就是「有时候退一句、有时候按了没反应」。
> 顺序播放时那条 1.5 秒规则照旧：「已经播过一会儿了，按上一句先回本句开头」在精听时更顺手。
>
> 判定逻辑在 `Subs/CueLoop.cs` 里，和界面无关，`--jumpsim` 会把这套规则连同真实的按键时序一起跑一遍。

> **字幕时钟有一条下限**：`AudioPlayer.Position` 不会报得比最近一次定位点更早。
> 原因是刚 seek 完那一小段声卡缓冲还没灌满，输出延迟那 120ms 扣不回来，
> 位置会被算到定位点之前 —— 界面据此判断「当前第几句」就会倒退一句，
> 单句循环于是把上一句当成循环句，表现出来就是「按一下上一句退了两句还来回弹」。
> 下限只夹掉这一小段，正常时刻的读数一点没变。

## 7. 收藏

听到好句子想留下来，按一下收进去，之后在「收藏」页统一复习。

**怎么收**：播放时按 `Ctrl+Alt+S`，或者在字幕条上右键「收藏本句」。
再按一次就是取消，菜单里的文字会跟着变成「取消收藏」——收没收过不用猜。

**收藏页**在「播放」后面，顶上三个筛选：

| 筛选 | 内容 |
|---|---|
| 全部 | 所有收藏，按节目名、句号排序 |
| 最近 | 新收的在前，最多 50 条 |
| 本节目 | **默认**。只看当前这一集的，按句号升序 |

每一行左边是一颗**实心星**（就是「已收藏」本身），点它取消收藏；**点整行的其它地方就直接跳到这一句并单句循环**，
一次点击进入精听。右边灰字是「节目名 · 第几句」，文件已经不在原来的位置时整行会变灰并给一条提示。

底下一行写着「共 N 句」，右边两个动作：**全部播放**（按当前筛选的队列一句一句连着放，一句放完自动跳下一条）、
**导出 .txt**（纯文本，带 BOM，记事本 / WPS 打开中文都不乱码）。

> 收藏存的是「音频文件路径 + 第几句 + 那一句的文字快照」，写在 `favorites.json` 里，
> 和 `config.json` 同一个目录（跟着 exe 走，换目录要一起拷）。
> 靠文字快照，字幕文件后来被改过也能把这一句找回来；实在找不到才退回按时间定位。
> 音频文件被删 / 搬走了，行还在，只是灰掉，不会静默消失。

## 8. 透明度与背景

两档透明度，鼠标位置决定：

| 设置 | 说明 |
|---|---|
| 移开 | 平时的不透明度，填 0~100 的百分数 |
| 悬停 | 鼠标移到字幕条上时的不透明度 |

**透明底**打开后只留文字，不画底板。

> 实现细节：底板用的是 alpha=1 的黑色，而不是完全透明。
> 因为 `AllowsTransparency` 的窗口是分层窗口，像素 alpha 为 0 的地方会被系统判定为鼠标穿透，
> 那样右键就点不到字幕条了。alpha=1 是 0.4% 的黑，任何背景下肉眼都看不出，视觉上等同全透明。

## 9. 快捷键

**七个功能的热键都能改。** 在「快捷键」页点按钮，然后按下新组合即可。

| 默认 | 作用 |
|---|---|
| `Ctrl+Alt+H` | 老板键：隐藏字幕条并暂停 / 再按显示并继续 |
| `Ctrl+Alt+Space` | 播放 / 暂停（也可以直接**左键点任务栏上的字幕条**） |
| `Ctrl+←` | 上一句 |
| `Ctrl+→` | 下一句 |
| `Ctrl+Alt+L` | 单句循环开 / 关 |
| `Ctrl+Alt+S` | 收藏当前这句（再按取消） |
| `Ctrl+Alt+[` | 字幕偏移 −100ms（字幕更早） |
| `Ctrl+Alt+]` | 字幕偏移 +100ms（字幕更晚） |

**老板键是「藏起来 + 停掉声音」一条龙**：只藏字幕条而让音频继续响，在工位上等于没藏。
所以一次按下同时暂停，再按一次显示字幕条并接着放。

> 续播是有前提的：只有「藏起来的时候本来在放」才自动继续。
> 本来就是暂停状态按的老板键，回来还是暂停——否则一按就自己出声了。
> 判定用一个 `_bossPaused` 标记，在 `ToggleBossKey()` 里。

**偏移那两个键一次走 100ms**，鼠标停在播放页的偏移输入框上会提示是哪两个键、各往哪个方向。
`Ctrl+Alt+[` 让字幕提前（数字变小），`Ctrl+Alt+]` 让字幕推后（数字变大）。

- 录制时 `Esc` 取消
- 必须带 `Ctrl` / `Alt` / `Shift` / `Win` 至少一个
- 两个功能绑同一个组合会被拒绝
- 被别的程序占用时，界面上会飘一行提示说明具体是哪一项

## 10. 托盘

关掉主窗口**不会退出程序**，会收进托盘继续播放，**不会弹任何提示**。

托盘图标左键单击或双击 = 打开主界面，右键菜单：

```
显示主界面
隐藏并暂停 / 显示并继续   ← 老板键，和字幕条右键里那项是同一个
播放 / 暂停
──────────────
退出
```

托盘菜单里的显隐项走的就是老板键：藏字幕条的同时把音频停掉，再点一次显示并接着放。

只有点「退出」才真的结束进程。可以在「常规」页关掉「关闭到托盘」，那样关闭即退出。

## 12. 诊断

```bash
LoafEar.exe --probe               # 任务栏实测数据 → probe.txt
LoafEar.exe --selftest            # 离线自检 → selftest.txt
LoafEar.exe --shot                # 主界面五个标签页 + 目录浮层 + 播放/暂停图标对照 → shots\tab*.png、dir.png、icons.png
LoafEar.exe --dirsim              # 目录浮层：开合、节目清单、点一行是否换过去 → dirsim.txt
LoafEar.exe --floatsim            # 悬浮字幕：勾上/拖动/上锁/取消 + 靠左靠右两种吸附算出的 x → floatsim.txt
LoafEar.exe --barshot             # 字幕条渲染 + 左键单击/双击自测 → shots\bar.png、barshot.txt
LoafEar.exe --menushot            # 右键菜单与二级菜单 → shots\*.png
LoafEar.exe --audiotest [file]    # 真实声卡播放测试 → audiotest.txt（会出声）
LoafEar.exe --loopsim [file]      # 单句循环 12 秒长跑，判「循环句会不会自己往后挪」→ loopsim.txt（会出声）
LoafEar.exe --jumpsim [file]      # 真窗口 + 真字幕条，连按四次「上一句」看落点 → jumpsim.txt（会出声）
LoafEar.exe --favsim [file]       # 收藏开关 / 老板键 / 偏移 ±100ms / 连播三句 → favsim.txt（会出声）
LoafEar.exe --makeicon [out.ico]  # 由品牌矢量重新生成多尺寸图标（默认 brand.ico）
```

`--barshot` 除了出图，还会打印一行自测结果：双击是否只触发一次「暂停 / 继续」。
点不动、双击没反应这类问题，先看这个。

`--jumpsim` 是「单句循环下按上一句乱跳」那个 bug 的回归入口：它开一个真窗口、挂真字幕条、
用真声卡放一集，从第 5 句起播，在第 3.0s / 3.3s / 3.8s / 5.5s 各按一次「上一句」，
逐拍记下位置、当前句、循环句和字幕条上真正显示的字，最后再跑 5 条跳句规则单测。
判据很直白：**每次按键之后，当前句与循环句都必须正好比按键前小 1，且此后不再自己变化。**
`--loopsim` 更轻，只验证循环本身不会往回漂。

`--favsim` 跑的是收藏那一整套：收 / 取消 / 再收、三种筛选的行数、老板键两下的显隐与播放状态、
偏移两个键各走 100ms 且输入框跟着变、最后「全部播放」三句连着走一遍看会不会卡在同一句。
它会真的读写**当前目录**的 `favorites.json`，所以在临时目录里跑，别在放着自己设置的那份旁边跑。

排查鼠标交互还可以开跟踪：设环境变量 `LOAFEAR_TRACE=1` 再启动，
每次左键按下都会记到 `bar-trace.log`（是否判成双击、落点），
启动各阶段和右键菜单的耗时则记到 `ui-trace.log`（扫目录 / 开声卡 / 托盘 / 菜单展开各花了多少毫秒）。平时不写盘。

启动慢、刚启动点不动这类问题，先看 `ui-trace.log`：哪一行和上一行差得最多，瓶颈就是那一步。

`--makeicon` 会把 `Brand/BrandIcon.cs` 里的路径数据渲染成 16/20/24/32/40/48/64/128/256 九档，
打包成 `brand.ico`，同时导出 `brand-preview-256.png` 与 `brand-preview-32.png` 方便看效果。
换图形只需改那一个文件再跑一次。设计稿里的分层（面包体、割口）和各自的填充色、描边宽度都保留在代码里。
**16 到 256 用的是同一套图形，不另做简化版**——只在 48 px 以下给描边一个最小设备像素宽度（0.45~0.75 px），
否则按比例缩出来的描边只有 0.1 px，轮廓会凭空消失，托盘图标看起来就和任务栏里的不是同一个。24 px 及以下的割口细到 2 px，
再套描边红色会被吃掉，这几档只留红色色块。

`--selftest` 不需要声卡和界面，验证七件事：

1. **变速比例**——3 秒源在 0.5× 下是否输出 6.000s、2.0× 下是否输出 1.500s（1.0 到 2.0 共六档）
2. **ASS 解析**——卡拉OK时间戳、颜色、粗斜体、`\fad`、`\an`
3. **字幕改写**——「保存」按钮走的就是这条路径：SRT 主句、ASS 主句、**折行中文句**、**双语折行句（主句与译文各改一次）**
4. **目录扫描**——字幕配对与自然排序（`E01 < E02 < E3 < E10`）
5. **自定义快捷键**——显示文本、重复检测、**八个默认键都在且互不重复**
6. **右键菜单**——项数、一级菜单里二级子菜单的挂载
7. **字幕条渲染**——富文本、逐帧更新、淡入淡出、**分页（每页起点 / 宽度 / 时间）**都不抛异常

`--audiotest` 会打印每次 `Read` 的返回值与 `Wasapi/WaveOut` 的实际状态，用来定位「加载成功但没声音」。

## 13. 已知限制

- **不支持多显示器副屏**：只贴主任务栏
- **不支持竖向任务栏**：只处理水平方向
- **字幕条高度固定 40 DIP**：任务栏本身只有 48 DIP，只放得下两行小字
- **变速有约 120ms 启动延迟**：SoundTouch 是块处理，需要先吞一段输入才吐输出
- **截图隐身依赖显卡驱动**：部分机器会变成「黑块」，反而更显眼，发现异常请关掉
- **不能以管理员身份运行**：`SetParent` 跨进程要求完整性级别一致，管理员权限下会静默失败，程序会自动降级成悬浮窗
- **节目菜单最多列 30 个**：更多的话去磁盘上整理目录

## 14. 技术要点

### 任务栏定位

```csharp
var taskbar = FindWindow("Shell_TrayWnd", null);
SHAppBarMessage(ABM_GETTASKBARPOS, ref data);   // 拿到任务栏矩形与朝向
```

Win11 25H2 里 `MSTaskListWClass` 是 `ReBarWindow32 > MSTaskSwWClass` 下的**隐藏孙窗口**，`FindWindowEx` 只找直接子窗口，按类名直接找它必然失败。能用的按钮区边界是 `ReBarWindow32` 的矩形。

### 嵌入方式

```csharp
CreateWindowEx(
    WS_EX_NOPARENTNOTIFY | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW,
    ..., WS_CHILD | WS_VISIBLE,
    x, y, w, h,
    FindWindow("Shell_TrayWnd", null),    // 父窗口 = 任务栏
    ...);
```

explorer 重启或分辨率变化后子窗口会被藏掉，所以每 800ms 用守护定时器校正位置并恢复可见性。

### 启动顺序：为什么字幕条要「迟到」

字幕条是 explorer 的**子窗口**。它的消息循环和主界面共用同一个界面线程，
一旦界面线程在忙（不取消息），explorer 把鼠标事件同步发过来就会一直等我们返回，
表现出来就是**整个任务栏连同鼠标一起卡住几秒**。

所以启动阶段严格按这个顺序走，任何一个环节都不许压在「字幕条已可见」之后：

1. 建主窗口（此时还没有字幕条，卡一会儿也没人能点）
2. 建字幕条窗口，但**先隐藏**
3. 后台线程扫听力目录、开声卡（`WaveOut` 初始化）、解析字幕
4. 托盘整套（WinForms `ContextMenuStrip` + `Shell_NotifyIcon`）交给**独立常驻线程**去建，
   界面线程一次都不碰
5. 预热右键菜单的模板/排版
6. 以上全部完成，才 `ShowWindow` 让字幕条出现

第 3、4 步是重点：这几件事在冷启动时各要几百毫秒到一两秒（本项目实测声卡初始化 ~100ms，
WinForms 首次建 `ContextMenuStrip` 更是要 **550ms**）。
以前它们排在字幕条显示之后，用户「刚打开就右键」时正好撞上，于是卡死；等这几百毫秒过去又好了。
现在第 3 步在 `Task.Run` 里、第 4 步在托盘线程上，界面线程只负责最后贴结果。

冷启动期间如果用户已经右键，位置会先记下来（`_pendingMenuPoint`），就绪后立刻补开菜单，这一次点击不会白点。

另外 `SubtitleBar.Reposition()` 不能在 `SetWindowPos` 里硬塞 `SWP_SHOWWINDOW`：
那会让窗口真实可见性和 `SetVisible` 的状态缓存对不上，之后叫它隐藏会被去重逻辑跳过，
字幕条就永远挂在任务栏上了。

### 播放输出为什么用 WaveOut 而不是 WASAPI

实测（Win11 25H2 + 板载声卡）：`WasapiOut` 在共享/事件驱动模式下会出现
**`PlaybackState` 一直是 `Playing`，但播放线程只拉了一次数据就再没回调**的情况，
表现为进度条不动、完全没声音，也不抛异常、不发 `PlaybackStopped`。

所以默认走 WinMM 的 `WaveOutEvent`（`DesiredLatency=120ms`，2 个缓冲），
只在 WaveOut 初始化失败时才退回 WASAPI。

### 字幕同步

**唯一时钟源是音频播放位置**，每 50ms 二分查找当前句。不用计时器累加——那样一集播完能差两秒。

### 配置文件必须用同一套序列化选项读写

`Save()` 用 `JsonStringEnumConverter` 把枚举写成 `"Auto"`，
`Load()` 如果不带同一个 converter，就会因为 `"Auto"` 转不成枚举而**整份配置报废**、
静默回落到默认值——用户表现为「设置每次启动都丢」。
